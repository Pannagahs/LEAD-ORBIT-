LeadOrbit: How Everything Is Interconnected

This page explains system flow, UI interaction, architecture, and how to build a simple web app using the same SVG screens. Read this as your single source of truth for "what is happening" and "how to implement it quickly".

Architecture At A Glance

Data flows from lead sources into a lead engine, then to 4 UI surfaces, and finally to business outcomes.

Source Layer Facebook, Google, Website, Offline Events
->
Lead Engine Dedup, scoring, assignment, SLA watch, reminder trigger
->
UI Layer Listing, Details, Management Board, Dashboard
->
Outcome Layer Faster contact, less leakage, better conversion visibility
Source Processing User Interface Business Outcome

Status Lifecycle And Ownership

Each lead moves stage by stage. Ownership and next action are visible at every point.

  • NewAuto-assigned, first-contact timer starts
  • ContactedCall outcome saved, follow-up task generated
  • QualifiedCustomer need and buying timeline captured
  • Test Drive ScheduledAppointment and reminder set
  • NegotiationDiscount and finance progress tracked
  • Won / LostFinal business outcome recorded

How The 4 Screens Are Connected

These screens are not separate designs. They are one continuous operational loop.

1. Lead Listing

Entry point for sales reps. Filter, prioritize, and take immediate action.

2. Lead Details

Drill-down context page. Notes, timeline, qualification, next best action.

3. Lead Management

Manager board for workload balancing, stage movement, and SLA intervention.

4. Dashboard

Business view for funnel health, source quality, rep performance, and aging risk.

Flow Step 1: Inbound lead appears in Listing Rep sees source, score, status, and urgency. Immediate action starts.
Flow Step 2: Rep opens Details for deeper qualification Rep captures intent, timeline, finance context, and adds notes.
Flow Step 3: Stage transitions update Management board Manager monitors queue movement and acts on blocked or stale items.
Flow Step 4: Dashboard aggregates everything KPI and funnel summarize what is working and where to optimize.

How To Build A Simple Web Application Using These SVG Files

If you want a basic clickable demo app, use this minimal structure and code approach.

Step 1: Keep current folder structure Put one HTML entry file in product-assessment and keep all screens inside product-assessment/mockups.
Step 2: Create app shell Create a sidebar and preview panel. On click, update image source with selected SVG. 
<img id="screen" src="mockups/screen-1-lead-listing.svg" />

const screen = document.getElementById("screen");
button.addEventListener("click", () => {
  screen.src = "mockups/screen-2-lead-details.svg";
});
Step 3: Add simple state model Keep a JavaScript object that tracks selected lead, status, owner, and last activity. Use that to update badges and summary cards. 
const appState = {
  selectedLeadId: "LD-1024",
  status: "Contacted",
  owner: "Neha",
  slaRisk: true
};
Step 4: Simulate workflow interactions Add buttons such as "Call Now", "Mark Qualified", and "Assign". Update local state so manager board and dashboard counters also change.
Step 5: Optional next level Replace static SVG preview with component-based UI (React/Vue) and use real API endpoints for leads, assignments, and metrics.
Tip: for assignment demo, static SVG-based navigation is enough. For production, move to dynamic components + backend APIs + authentication + audit logs.

Current file is a standalone explainer UI. Open it in browser and use the navigator to inspect all screens and understand end-to-end architecture.
